# קופת מעשר: אפליקציית Flutter לאנדרואיד

הפרויקט בנוי לפי הארכיטקטורה שפוענחה מ"ניהול כספים" (`ru.innim.my_finance`) ומותאם לניהול מעשר וחומש.

> **חשוב:** לא יכולתי לקמפל את הפרויקט בסביבה שלי, כי אין בה גישה להורדת Flutter SDK. הקוד נכתב בזהירות, אבל ייתכנו שגיאות קטנות בקומפילציה הראשונה. אם `flutter run` מציג שגיאה, העתיקו אותה אליי ואתקן.

---

## 1. מה צריך להתקין (פעם אחת)

1. **Flutter SDK** (גרסה 3.24 ומעלה):
   - הורדה: https://docs.flutter.dev/get-started/install/windows/mobile (יש גם עמודים ל־Mac ול־Linux).
   - מחלצים לתיקייה, למשל `C:\flutter`, ומוסיפים את `C:\flutter\bin` למשתנה PATH.
2. **Android Studio:**
   - הורדה: https://developer.android.com/studio
   - בהתקנה מסמנים Android SDK ו־Android SDK Command-line Tools.
   - בתוך Android Studio: Settings → Plugins, ומתקינים את **Flutter** ואת **Dart**.
3. **בדיקה:**
   ```
   flutter doctor
   flutter doctor --android-licenses
   ```
   מאשרים את כל הרישיונות. כל השורות הרלוונטיות צריכות להופיע עם ✓.
4. **הטלפון:**
   - בהגדרות, "אודות הטלפון": לוחצים 7 פעמים על "מספר Build" כדי להפעיל מצב מפתח.
   - באפשרויות מפתח: מפעילים "ניפוי באגים ב־USB".
   - מחברים את הטלפון בכבל.

## 2. יצירת הפרויקט

```
flutter create --org com.yourname --project-name maaser_app maaser_app
cd maaser_app
```

1. **קוד:** מחליפים את התיקייה `lib` כולה ואת `pubspec.yaml` ו־`analysis_options.yaml` בקבצים מהתיקייה הזו.
2. **שם האפליקציה:** ב־`android/app/src/main/AndroidManifest.xml` משנים את השם:
   ```xml
   android:label="קופת מעשר"
   ```
3. **גרסת אנדרואיד מינימלית:** ב־`android/app/build.gradle` (או `build.gradle.kts`) בודקים ש־`minSdk` הוא לפחות 24, כמו במקור:
   ```
   minSdk = 24
   ```
4. **תלויות:**
   ```
   flutter pub get
   ```

## 3. הרצה ובנייה

- **הרצה על הטלפון המחובר:** `flutter run`
- **קובץ התקנה:** `flutter build apk --release`
  - הקובץ נוצר ב־`build/app/outputs/flutter-apk/app-release.apk`.
  - מעבירים אותו לטלפון ומתקינים. צריך לאשר "התקנה ממקורות לא ידועים".
- **חתימה קבועה (מומלץ):** בלי חתימה קבועה, כל בנייה חדשה תדרוש להסיר את האפליקציה הקודמת, והנתונים יימחקו. יוצרים מפתח לפי https://docs.flutter.dev/deployment/android#signing-the-app.

## 4. העברת הנתונים מאפליקציית ה־HTML

1. בתפריט, בוחרים "גיבוי ושחזור" ואז "ייבוא מאפליקציית ה־HTML".
2. בוחרים את הקובץ `maaser-data.json`, או קובץ גיבוי שנשמר מגרסת ה־HTML.
3. מה מיובא: קופות ויתרות פתיחה, קטגוריות עם צבעים, כל הפעולות עם החלוקה למעשר ולחומש, תשלומים קבועים ואחוזי החלוקה.

## 5. מבנה הקוד, ומה נלקח מניהול כספים

| קובץ | תפקיד | מה נלקח מהמקור |
|---|---|---|
| `models.dart` | מודלים: קופה, קטגוריה, פעולה, תשלום קבוע | סכומים כמספר שלם באגורות, UUID, `created`/`modified`, מחיקה רכה (`isRemoved`), `useCount`/`lastUse` לקטגוריות, `lastDate` לתשלום קבוע (כמו `lastTransactionDate`) |
| `db.dart` | SQLite (`sqflite`) | `user_version` עם מקום למיגרציות `ALTER TABLE` (במקור הגיעו לגרסה 35), טבלת key-value להגדרות, החלפת כל הנתונים בטרנזקציה אחת |
| `store.dart` | כל הלוגיקה, בתפקיד ה־Bloc | יתרה = פתיחה + תנועות; תקופות (יום, שבוע שמתחיל ביום ראשון, חודש, שנה); השלמת תיאורים לפי שכיחות, כמו `GROUP BY comment ORDER BY count DESC`; מחיקת קטגוריה עם העברת הפעולות; תשלומים קבועים שנוצרים בפתיחת האפליקציה |
| `backup.dart` | גיבוי ושחזור | **בדיוק המנגנון שפוענח:** ZIP עם ה־DB וקובץ `backup_meta` שמכיל `{"version":1,"hash":…}`, וה־hash הוא `SHA256(salt + sorted(base64(MD5(file))))`. בשחזור: `temp_restore_…`, בדיקת meta, עותק `temp_rollback_…` וחזרה אליו אם יש כשל |
| `ui/home.dart` | מסך ראשי | סרגל עליון עם יתרה, לשוניות, צ'יפים לתקופה, חצים וגרירה, תרשים עוגה, שורות קטגוריות, כפתור + |
| `ui/edit_tx.dart` | הוספה ועריכה | רשת קטגוריות עגולות, צ'יפים היום/אתמול/שלשום, תיאור עם הצעות, "חזרה" |
| `ui/manage.dart` | תפריט, קטגוריות, קופות, אחוזים, תשלומים קבועים, גיבוי | |

### ההתאמות למעשרות
1. **הכנסה:**
   - נרשמת בסכום המלא.
   - **אוטומטית:** 10% נכנסים למעשר ו־10% לחומש. האחוזים ניתנים לשינוי.
   - **ידנית:** מזינים סכום לכל קופה.
2. **קופת צדקה:**
   - קטגוריית הכנסה עם הסימון `full`.
   - נכנסת במלואה למעשר, בלי חומש.
3. **תרומה:**
   - יוצאת ממעשר, מחומש, או "משתיהן".
   - "משתיהן": קודם מהמעשר עד היתרה שלו, והשאר מהחומש. בעריכה, החלוקה מחושבת מחדש בלי לספור את התרומה עצמה.
4. **פיצול לקופות:** כל פעולה שומרת `splits`, כמה נכנס לכל קופה או יצא ממנה. היתרה של קופה היא יתרת הפתיחה ועוד כל התנועות שלה.
5. **לשוניות:**
   - **הכנסות:** סך הכנסות מלאות, ופירוט כמה מזה הלך למעשר, כמה לחומש וכמה הגיע מקופת צדקה.
   - **מעשר / חומש:** תרומות לפי קטגוריה, ושורה של נכנס, נתרם ויתרה.
6. **תשלומים קבועים:**
   - תדירויות: יום, שבוע, שבועיים, חודש, חודשיים, רבעון, חצי שנה ושנה.
   - בתדירות חודשית נשמר יום החודש. בחודש קצר יותר נבחר היום האחרון בחודש.
   - חידוש אחרי השהיה לא רושם את התקופה שבה התשלום היה מושהה.
   - מחיקה לא מוחקת פעולות שכבר נרשמו.

## 6. הרחבות אפשריות (לפי מה שיש במקור)

- **התראות ותזכורות:**
  - חבילה: `flutter_local_notifications` + `timezone`.
  - הרשאות: `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` ו־`RECEIVE_BOOT_COMPLETED`, כמו במקור.
  - שימושים: תזכורת יומית, ועדכון על תשלום קבוע שנרשם.
- **ווידג'ט למסך הבית:**
  - חבילה: `home_widget`.
  - במקור יש שני ווידג'טים: יתרה עם "+ הוסף", וכפתורי הכנסה ותרומה.
- **נעילה:**
  - חבילה: `local_auth` (טביעת אצבע).
  - במקור משלבים קוד PIN בן 4 ספרות עם אימות ביומטרי.
- **ייצוא ל־Excel או CSV:**
  - חבילות: `excel`, או כתיבת CSV ידנית.
  - במקור יש ייצוא ל־PDF, Excel ו־CSV.
- **סנכרון בין מכשירים:** דורש שרת. במקור כל שינוי בכל שדה נרשם בטבלת `sync_action` עם מספר רץ (`usn`), ונשלחים לשרת רק השינויים שעוד לא נשלחו. פשוט יותר: לשמור את קובץ הגיבוי ב־Google Drive.

## 7. מה בכוונה לא נכלל

- פרסומות, אנליטיקה, מנוי, חשבון משתמש ושרת. כל אלה קיימים במקור, ולא נדרשים כאן.
- קופות נפרדות, כמו "שווי מעשר ראשון". לפי בקשתך הן לא רלוונטיות.
- אייקונים: השתמשתי באייקונים של Material, שמגיעים עם Flutter בחינם, ולא באייקונים של ניהול כספים, שהם יצירה של המפתח.
